The premise that priced itself wrong

Ticket 41 §3 opened by stating that bsc is single-file. It is not, and measuring that is what decided the ticket — the fork it framed as expensive turned out to be an accumulator on a loop that already exists.

The one-line result

§3 — the compiler re-checks a dependency's source, and owns the dependency graph. A build tool names the source root and the file set, never the order.

§4 — index.bs holds everything except functions. One-function-per-file has no exception, enforced as an error rather than a convention.

Both were the last two open sections. §1, §2 and §5 landed on 2026-08-15 but were answered-and-unverifiable for a day, because neither unqualified names nor namespace resolution can be checked without knowing where the checker gets another module's types. Closing §3 is what made yesterday's work real.

What the measurement changed

The false premise. §3's opening sentence read "the compiler is single-file (bsc FILE.bs, one module declaration, one .beam)". That is wrong, and the whole cost estimate rested on it.

$ bsc Alpha.bs Beta.bs
exit=0
beams: ./Alpha.beam ./Beta.beam

compile_only/2 is already [file(F, Opts) || F <- Files] — a map over a file list. What is single-file is the environment, not the invocation. So fork A does not need a new CLI, a new entry point or a new artefact; it needs the loop that already exists to carry an accumulator.

The second measurement is the one that makes it safe. A file calling a function defined in another file of the same invocation is rejected — and rejected identically in both argument orders:

$ bsc Alpha.bs Gamma.bs     # Gamma calls Double/1, defined in Alpha
Gamma.bs:5: error: Eight calls Double/1, which nothing declares
$ bsc Gamma.bs Alpha.bs     # same error, order reversed

There is no accidental leakage and no order-dependence already baked in. Whatever cross-module visibility gets added is entirely the new rule — not the new rule plus an undocumented one, which is not something a design gets for free.

Why the build-tool option is not a third option

The fork looked like three choices. It is two, and the third collapses into the one already rejected — which is what settles it on mechanism rather than preference.

The exemplars had already answered it

All three index.bs files in examples/exemplars/ were written before the question was asked, and all three hold zero functions — only using, type, record and behaviour. That is evidence rather than prediction: nobody reached for the exception.

The mechanism is write_scope

The standing constraint makes one function per file a bounded blast radius — no merge conflicts between agents working different operations. index.bs is the module's contended file by construction: every new type, record and using line lands there.

Permitting functions would merge the most-contended file in the module with the one thing file-per-function exists to isolate. Two agents adding unrelated functions would collide in a file neither of their functions is in — the exact failure the rule was chosen to prevent, arriving through the one file it did not cover.

The write-cost objection does not survive the standing constraint: ceremony is near-free because agents author these files, and read cost points the same way — an exception gives every search for Total/1 a second place to look. A private helper gets its own file with ticket 40 §2's private, costing one file and zero runtime.

An error, not a convention. {function_in_index, Name, Line}. An ungated convention decays exactly as the exemplars' dead dialect and LANGUAGE.md's true claim did — both cases where prose asserted a rule nothing enforced.

What this leaves owed

  • Four checks, specified and unbuilt, belonging to the feature that implements the module system: {module_path_mismatch, …} (§5), {function_in_index, …} (§4), §2's ambiguity rule, and §3's environment-threading.
  • A cycle rule for mutually importing modules. F6's cyclic-alias guard is the precedent — refuse by name rather than expand — but it is a mechanism the implementing feature meets, not a fork this ticket owns.
  • Re-checking cost. Compile-time only, no correctness consequence. If it ever bites, the fix is a cache — which is fork B under a different name.
  • Ticket 47 · ENG-219 — the import alias, spun out rather than absorbed.

Why the alias became its own ticket

41 parked using Orders = Shop.Orders with a note that §2 inverted the argument against it. An alias was shelved as a pure read cost — the reader has to find the alias line to learn what Orders means. That assumed the competing form was a qualified name, carrying its source in the call. §2 made the competing form a bare name carrying no source at all, and against that an alias is the more explicit spelling.

The ticket said it "should be re-asked rather than inherited". Re-asking is a decision, and this repo's rule is that naming a decision you need is raising a ticket — which does not count as raised until the file and the issue both exist. That rule was written after F2 sat takeable-looking for a day on blockers no query could see.
