The Honest Crash

The ticket was charted as a conflict between enforced totality and BEAM culture. There was no conflict — let-it-crash is how you spell partiality.

Unchanged

Every case your types admit has a clause — and everything from outside is a term until you match it.

Ticket 11 chose this sentence to be stable whichever way ticket 12 went. It is — but it is now literally true rather than aspirational, because a function that leaves a case uncovered does not compile.

Half the question had already been answered

The ticket offered four candidates. Two were dead before it was picked up. “Total only where the input type is fully known, and dynamic elsewhere” and “totality at typed boundaries, abandoned at dynamic ones” both presuppose a dynamic region to abandon totality to, and ticket 11 removed it. Every argument carries a declared type, term is a declared type, and exhaustiveness against term is perfectly well-posed.

So the real question was only ever about enforcement strength — and the ticket's own list was missing the strongest option, which is the one taken: a plain type error, with no opt-out at all.

Ticket 21 supplied the discriminator, and it is the sharpest evidence on the map: Microsoft's named successor to Code Contracts was nullable reference types — the contract that survived is the one that became a type. A warning-level exhaustiveness check is precisely a contract that did not become a type. Ticket 07 found C# 15's unions do exactly that, and Elixir 1.20 ships redundancy only. If beam-sharp's guarantee is also warning-shaped, ticket 00's differentiator evaporates.

What the checker does with a residual

Ticket 01 flagged the tension this resolves: a catch-all makes a function total and therefore unfalsifiable. Under a hard error, _ would otherwise become the universal escape, since the cheapest way to satisfy a compiler is always to stop telling it things. But a blanket ban is impossible — ticket 11 requires a catch-all wherever a term arrives.

The set theory already committed to supplies the discriminator. A closed residual is built only from declared cases, so the compiler knows each by name and can make you write them. An open residual contains an unbounded top — ticket 10 made atom the cofinite top with exactly this representation — and cannot be enumerated, because a foreign sender chooses the inhabitants.

The showcase lands on the permissive side without special pleading: handle_info receives OTP's {'EXIT', pid, reason}, {'DOWN', …}, timeouts and strays, all typed term. What gets caught is the domain union where a named case was skipped.

Accepted as an invention. This is tier 3 on the borrow heuristic. C#'s _ in a switch arm is just a pattern and TypeScript's default is just a branch — neither audience expects _ to be conditionally legal, so it fails the read-on-sight test. It was taken because the alternative fails a more expensive one: a uniform _ puts the headline guarantee one character from being switched off, silently, with no trace in the diff. Ticket 25 owes the empirical check — how often closing a finite residual is genuinely wanted.

Two rules that turned out to be one

The candidate answer for the boundary clause was positional: crash in a call, continue in a loop. Writing both out is what killed it.

Call position 
(:reply, int, Account) HandleCall(term, From, Account);

((:withdraw, amt), _, a) when amt <= a.Balance
                          -> (:reply, a.Balance - amt, a);
((:balance), _, a)        -> (:reply, a.Balance, a);
(_, _, _)                 -> raise :bad_request;
Loop position 
(:noreply, Account) HandleInfo(term, Account);

((:DOWN, _, :process, pid, _), a)
                          -> Accounts.Detach(a, pid);
((:timeout, _), a)        -> Accounts.Sweep(a);
(_, a)                    -> (:noreply, a);

Look at the return types rather than the positions. (:reply, int, Account) contains no honest value for an unrecognised request — the alternatives to crashing are fabricating an integer, a lie the type system will accept, or not returning, which is unavailable. (:noreply, Account) makes (:noreply, a) completely honest: the message was not addressed to you, and saying so is the declared behaviour, not silence.

So in each case there was exactly one honest thing to write, and the signature determined which. The position was never the operative fact. The test is wanting the other behaviour — you do not reach for a different rule, you widen the type:

(:reply, int | :bad_request, Account) HandleCall(term, From, Account);
...
(_, _, a)                 -> (:reply, :bad_request, a);

The crash disappeared because the author declared somewhere for the failure to go. That is ticket 21's discriminator again, applied to this ticket: the decision became a type — visible in the contract a caller sees, rather than a convention a reviewer must police. And it settles the question ticket 11 left open: ValidateAs<T> returning T | :error is not an exception to a rule, it is a signature that declared a failure channel.

The six decisions

  1. Enforcement

    Hard error, no opt-out

    A non-exhaustive function does not compile. Being partial means writing a clause that crashes.

    Rejected — PureScript's Partial. The most attractive option on the table, and it maps unusually well onto let-it-crash. Ticket 19 found it erased before codegen, so it buys nothing at runtime; and a propagating constraint is a second effect system running beside an algorithm ticket 04 found has no complexity bound in the literature. Its one real benefit returned anyway — see none.

  2. Catch-alls

    Legal only over an open residual

    _ is permitted where an unbounded top remains, and is an error where the residual is closed and the case names are known.

    Rejected — a uniform _. Invents nothing and reads on sight, but leaves ticket 01's unfalsifiability problem entirely unaddressed.

  3. Boundary

    Signature-directed

    Write the honest value your return type admits; raise only where it admits none.

    Rejected — the positional rule. Would have needed a definition of “call” versus “loop” at the edges, and nothing would check it. It is the shadow the return types cast.

  4. Lattice

    The bottom type is none

    First-class and writable, mirroring ticket 11's override for term so one heritage names the whole lattice. Diagnostics print residuals, and an exhaustive function's residual is the bottom — a type an agent reads but cannot write would be a gratuitous asymmetry.

    Rejected — TypeScript's never. The honest tier-1 borrow and it dodges a false friend, but it splits the lattice across two heritages in the one place both names are always read together. Known cost: none is a type with no values; the prelude's :nothing is a value meaning absence. Stated in the spec, as as already is.

  5. Crash

    Spelled raise

    Tier-2 from Elixir, verified to produce the error class. A user may still declare none Reject(Reason); — a named, greppable, type-checked crash site, which is the Partial benefit recovered from the lattice rather than from a constraint system.

    Rejected — C#'s throw. C# 7 already made it an expression with exactly the right typing, so it fails on semantics, which is what tier 1 is about: the BEAM's throw is the catchable class, so a BEAM reader would read recoverable where the language means fatal. Also rejected — an ordinary function typed -> none: no grammar change at all, but lexically identical to a call, with the callee's signature in another file. Both neighbours had that option and chose a keyword.

  6. Reversal

    The failure arm is always emitted

    This ticket's own body argued for omitting it when exhaustiveness is proved, calling it “a concrete, measurable payoff”. Measured, it is not — see below.

    Rejected — omission when exhaustive. erlc omits the arm only when coverage is proved over all terms, so nothing can defy it. beam-sharp's exhaustiveness is over the declared type, a strictly smaller set — and ticket 21 established there is no link-time closure on the BEAM, so “no foreign caller exists” is unprovable.

What omitting the failure arm actually costs

Method: compile to Core Erlang, strip the compiler_generated match_fail clause, recompile with +from_core, and call with a value no clause matches.

Measured on OTP 28 — prototype 12a
Error classTop stack frameSize
With the arm error:function_clause {partial, [c], [{file,…},{line,28}]} 832 b
Without error:if_clause {partial, 1, []} 792 b

40 bytes. 4.8%. What it buys is the wrong error class — if_clause, for a failure with no if in it — an arity in place of the offending argument, and no file or line. The surprise is that omission does not produce undefined behaviour or a silent fall-through: it produces a crash that mislabels itself, so you pay failure's cost without getting the information failure normally buys.

That frame is the property this project has twice identified as most valuable. Ticket 04: the residual is the missing clause. Ticket 23: what diagnostics owe an agent in a loop. {partial, [c], …} is the runtime analogue — it hands you the exact value that defied the types.

So the ticket's second explicit ask answers itself. If a clause is proven exhaustive but the runtime value defies it, does the process still die cleanly? Yes — function_clause, naming module, function, offending argument, file and line, which is what a supervisor should log. Deliberately paid for.

Where the saving could still be had

One route recovers the 40 bytes honestly: omit the arm only where a boundary guard has already rejected defying values. That is sound rather than optimistic — but the guards are ticket 18's decision, and 18 remains blocked on the deferred ticket 22. Restricting omission to non-exported functions collapses into the same thing, since a foreign value entering through an exported function reaches private ones unchallenged.

There is also an alignment worth carrying to ticket 13. Omission is only a choice on the Core Erlang path. Emitting Abstract Format means erlc inserts the arm and it cannot be suppressed — so the target ticket 02 favours makes the safe answer free, and only the Core path, which already forfeits -spec and Dialyzer, offers the 40 bytes at all.
