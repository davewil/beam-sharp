The One-Way Door

The ticket arrived with five findings already stacked against Core Erlang. None of them is the reason to record — a sixth fact subsumes them all, and it was not in the ticket.

The decision

The compiler emits the Erlang Abstract Format.

Recorded on reversibility, not on any of the five. .abstr → Core is a compiler flag, with OTP performing the translation. .core → abstract forms does not exist. This is the side of the door that keeps both rooms.

Five findings pointing one way is not an argument

The ticket had accumulated ticket 02's silent -spec loss, ticket 19's no-evidence-against, ticket 12's “third strike”, ticket 10's atom obligation, and the observation that LFE left Core Erlang in January 2018. All true, all pointing at the Abstract Format. A sixth recap of why Core Erlang loses would not have been a resolution.

What was missing is that ticket 02 framed the three targets as a ladder of increasing cost — bytecode dearest, Core in the middle, Abstract Format cheapest. Measured, they are not a ladder. They are a door that opens once.

Reversibility, measured on OTP 28.5
DirectionCommandResult
.abstr → Coreerlc +from_abstr +to_coreWorks — OTP does the translation

State it this way in the spec, because it is the form of the argument that survives new evidence. A future finding favouring Core Erlang would still have to explain why it is worth walking through a door that does not open again.

The failure mode matters more than the fact. Ticket 02 reported that a .core-built beam loses its -spec. Measured, the chunk is not missing — it is present and empty. A missing chunk is something Dialyzer can complain about. An empty one is something Dialyzer reads successfully and learns nothing from. That is the same shape as ticket 10's uninterned-atom trap: both are silent failures in the codegen layer, and a target chosen without checking either would fail quietly.

Core Erlang's one live advantage was already spent

It is worth naming what the decision did not cost, because the ticket left it open. Ticket 02 found Core Erlang's when is strictly wider than Erlang's guard grammar — a genuine capability the Abstract Format cannot match.

It buys nothing here. Ticket 09 fixed the discriminability vocabulary to the BEAM guard set, and ticket 08 committed guards to the same set via the expansion rule. The wider when has nothing left to express. Ticket 12's failure-arm omission is the only other Core-only capability, and ticket 12 had already decided against using it — so the Core path's remaining advantage was a saving nobody wanted, on a target that fails Dialyzer silently.

The contract is the forms, not the function call

The decision is a sequence of abstract-format forms, with a standing obligation attached: the frontend must never depend on in-process compiler state, so serialising the forms and shelling out to erlc +from_abstr always works. Verified — it builds a working module with no .erl anywhere on disk.

Without the obligation, a frontend drifts into parse transforms and shared state, and the text route quietly stops working precisely when someone wants to rewrite the frontend in another language. Keeping the promise is cheap now and unrecoverable later — the same reasoning ticket 11 used when it rejected higher-order contract wrapping as reversible-if-deferred.

What it buys: the compiler's host language is genuinely open. The walking skeleton need not be a BEAM program, which removes a constraint from that fog patch.

What it costs, permanently: erl_syntax and merl are foreclosed. They are the standard abstraction over Abstract Format drift, and they require a BEAM-hosted frontend. That is why the churn mitigation is a pinned OTP range proved by a CI corpus — current and previous two majors — rather than a library.

The range is provisional. +from_abstr is confirmed on OTP 28.5 only, because that is what is installed. Confirming it on the oldest supported release is work the walking skeleton owes, and the range is not real until then.

Source-only sub-modules, and an objection that turned out to be false

Sub-modules are source-only — one .beam per aggregate, not one per operation. Per-function hot code loading is rejected, not deferred.

Prototype 01d recommended this on four grounds but recorded one real cost: the sub-module structure is “a source fiction the runtime does not know about”, so a crash would name the aggregate rather than the file the programmer wrote. On this target that is largely false. A file attribute may appear repeatedly mid-module and re-points every form after it — the mechanism Elixir and LFE use to attribute generated code to original source.

%% two functions, ONE beam module, TWO source files
total/1 crash: {'Shop.Orders.Order',total,[99],[{file,"Order/Total.bs"},{line,42}]}
apply/1 crash: {'Shop.Orders.Order',apply,[99],[{file,"Order/Apply.bs"},{line,7}]}

So source-only keeps per-sub-module crash reports, dbg locations and debugger positions. Its remaining cost is narrower than 01d thought: the compiler owns a module abstraction the BEAM does not share, and every tool integration must translate.

Note the coupling this exposes. The repair depends on annotations surviving into the beam — which is exactly what the Core Erlang path discards. Had ticket 13 chosen Core, source-only would have cost its observability after all. The target choice and the sub-module choice are far more entangled than the ticket assumed.

Every function publishes a type, even when Erlang cannot spell it

A -spec is emitted for every function whose beam-sharp type is known. Where a set-theoretic type has no Erlang spelling — the grammar has no negation, and expresses intersection only as an overloaded spec — the compiler widens to the nearest expressible supertype, ultimately term().

A widened spec is sound: never a false claim, only a weak one. And it is silent — -Wunderspecs and -Wspecdiffs both turn warnings on and are off by default, so widening costs precision rather than noise.

The rejected alternatives, and why
OptionWhy not
Omit the specLeaves functions publishing nothing, and the boundary between “precise” and “absent” is invisible to a consumer.
Refuse to compileBans legitimate set-theoretic types from the exported surface to satisfy a weaker language's grammar.
Emit Erlang source textMore churn-resistant and human-readable, but -file("X", 42) occupies the line it names, so every line number becomes arithmetic. Annotations are simply exact.

What this does to the rest of the map

The sharpest consequence removes an argument rather than adding one.

  • Argument withdrawn

    Ticket 18 was told guards were the only route to a saving

    It reads: “emitted boundary guards are the only sound route to the codegen saving” of ticket 12's omitted failure arm. That saving does not exist on this target. erlc inserts the match_fail arm itself and there is no way to suppress it from the Abstract Format — visible in the generated Core as a clause beam-sharp did not write.

    So ticket 18's remaining motivation for emitting guards is silent unsoundness alone — ticket 06's third outcome. Narrower, and decided on honesty rather than bytes.

  • Coupling discharged

    13 and 18 no longer have to be decided together

    The ticket said twice that they must be, “or ticket 06's spec recommendation withdrawn”. That coupling was conditional on the Core Erlang branch, where -spec is lost. Choosing the Abstract Format dissolves it.

    This matters practically: ticket 18 is blocked behind the deferred ticket 22, so a genuine joint decision was structurally impossible this session. Ticket 06's recommendation stands unwithdrawn instead.
