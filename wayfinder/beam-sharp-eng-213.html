The 453-Character Error

Forty singleton clauses leave a residual of forty-one disjoint intervals. What the compiler prints was settled by measuring it — and two of the ticket's own premises did not survive the measurement.

The artefact

Premise 1 — measured false

The ticket asserts that forty-one intervals “therefore lower to forty-one heads”, and builds its hardest question on that. They do not. heads/2 splits on the tuple part — one product per argument position — and a union of intervals lives inside a single argument. So today it is one head, and the forty-one-head claim describes ticket 23 §2's lowering, which is unbuilt.

That correction matters because it turns Hole 1's conclusion — “the prose cannot summarise the residual alone, the head is the larger artefact” — from a fact into a conditional about future behaviour. One rule then covers both, and the ticket's two rendering problems collapse into one.

What it prints instead

scattered.bs:3: error: Classify is not exhaustive
  no clause matches:
    Classify(int <= 9 | 11..19 | 21..29 | ... (38 more)) -> ...

The prose prints the exact form with a stop in it — three cases, then the count. Nothing else summarises: not the term, not the synthesised head, and no complement is computed.

Why this shape and not the other four

The four candidates in the ticket are not four formats. Three of them replace the residual with a description of it; one is the printer the compiler already has, with a stop. Every number below is measured on the same forty-one-interval residual.

The narrowest form is not automatically the best one

Cardinality is the shortest and it is useless: over int the residual is unbounded, so it reads unbounded unnamed values — twenty-four characters of nothing. A shape that degenerates on the open residual cannot be the general one, and until F2 lands every residual is open, because int is the only integer type the surface has. The same defect sinks bounds and count.

The chosen shape wins on not being a second format

At three cases or fewer it prints byte-identically to today. So Hole 3's “why did the format change” confusion cannot arise — there is nothing to switch into. Every rival must switch, because none of them can render a two-interval residual without being worse than the enumeration, and none of them says what the missing case actually is.

The two consumers have opposite needs, which is ticket 23's split and the reframing this ticket started from. The finding is that only one of them ever needed a decision.

The unit switches once, and naming the stage is load-bearing

Caught in review — the ticket's own failure, in miniature

The rule first shipped as “print at most three heads”. That truncates nothing today, because the correction above had just established that today there is only one head — so F2.4's expected string asserted a behaviour the decision did not specify.

The rule was stated in the units of the premise it had just measured false. It now names its live unit per stage.

StageWhat the printer enumeratesWhat “three” counts
Today, before 23 §2 intervals inside one argument of one head line intervals
After 23 §2's lowering one head line per case heads

Counting heads is what the rule must become after §2, and that half is load-bearing: a residual over a two-argument function is a product, so the head count is ≥ the interval count, and an interval rule would print an unbounded number of lines the moment a second argument had a residual too. The implementation note for F2 is therefore to truncate over the rendered sequence rather than over intervals specifically — then §2 costs it nothing.

The complement, and why it lost

Premise 2 — measured false

The ticket refuses to commit because “for an unbounded int the complement is not finite”. That is wrong: the complement of the residual is the covered set, which is finite whenever the clauses cover finitely much — 25c's case exactly. It loses on size instead.

CaseexactcomplementVerdict
40 contiguous singletons over int2022loses
40 scattered singletons over int432245wins, still 245
40 contiguous over 0..255, closed1125loses
40 scattered over 0..255, closed404237wins, still 237

The residual and the covered set are long together. A covered set dense enough to state as a short exclusion is one that made the residual coalesce; a residual that sprawled did so because the covered set was scattered, which its own rendering then is. The ticket's intuition — “forty named singletons out of a bounded octet is small to state as an exclusion and large to state as a union” — is measurably false in the very case that raised it: every 0..255 except 5 | 10 | … | 200 is 237 characters.

The threshold's unit, measured rather than argued

Hole 3 says the units disagree — “three intervals over int render longer than twenty over 0..255”. They do not, including in a row built adversarially to break it.

Both columns order every case identically, so character length is not load-bearing and the tie goes to the unit that is stable and easy to test. And there is no threshold in the tunable sense: this takes Hole 3's “no threshold at all” option, which the truncated-exact shape makes free, since always-on costs a small residual nothing. No flag, no switch.

The one thing left to you

Ticket 12 §2 makes a catch-all an error over a closed residual. So once F2 lands, this program has forty-one clauses to write and no _ to write instead — the enumeration is the checklist, and three of forty-one is a third of a percent of it.

type Octet = int where value >= 0 and value <= 255

atom Classify(Octet n)

Classify(5)   -> :known
Classify(10)  -> :known
// … thirty-eight more, none contiguous
Default taken

Truncate anyway, both cases identically. The term keeps all forty-one and bsc --api is where a consumer goes for them; a forty-four-line error message is not more actionable than a five-line one plus a query. Printing in full for closed residuals also reintroduces exactly the format switch this shape was chosen to avoid, keyed on something the reader cannot see.

The delta if you want the other answer is one argument. heads/2 takes the residual's openness — which the checker already knows, because 12 §2 already tests it — and passes all instead of 3. It touches neither the term nor the descriptor, so F2 is unblocked either way and this flips later without a breaking change.
