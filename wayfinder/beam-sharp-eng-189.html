Terms, Not Prose

The ticket asked whether a compiler could hand an agent a machine-readable diagnostic. The platform has shipped three such channels for years — and throws the best one away at the command line, which is exactly where the consumer is standing.

The decision

The diagnostic is a term. The prose is a pure function of it.

Borrowed, not invented: compile:file/2 already returns {Location, Module, Descriptor} and derives its string through format_error/1. beam-sharp publishes that term at the CLI, freezes the descriptors an agent acts on, and refuses to approximate the ones it cannot lower.

The premise was wrong in the language’s favour

The ticket was written as though a machine-readable diagnostic had to be designed. It does not. Measured in 23a, this platform builds one at compile time, keeps a faithful copy of everything it emitted in the artefact, and carries a structured cause at runtime. What it does not do is deliver the first of those to anyone: erlc -h has no flag — not JSON, not a diagnostic mode, nothing — that recovers the term it just built.

That reframes ticket 18’s Elm anti-example. Elm’s port rejection collapses to a bare URL under --optimize because Elm’s runtime had no structured-error mechanism to lose. The BEAM has had one since OTP 24. Elm’s failure was never inevitable, and erlc’s is the same failure one layer out — the value exists, and the boundary hands out a string.

The compiler synthesises heads, never bodies

A residual is a set of values; a clause head is a pattern plus a guard. Lowering one to the other is a real compilation step, and the compiler owns it so that consumers do not each invert it differently. The skeleton does not do this yet — measured, it renders type expressions into argument position, and none of the three is paste-able:

Classify((:error, atom)) -> ...     // `atom` sits where a binder belongs
Classify(int <= -1)      -> ...     // real head: Classify(n) when n <= -1
Classify(atom \ (:ok))   -> ...     // real head: Classify(a) when a /= :ok

The line that keeps this trustworthy is that a head is derived and a body is a guess. A synthesised head cannot be wrong — it is the residual, respelled. A synthesised body would be the compiler choosing :unhandled over :bad_request, and a suggestion that is wrong in content is what makes an agent stop trusting the whole channel. That single line decided three questions in this session.

The rule that did work rather than decorating

The ticket’s fourth section — read and review cost keeps full weight, verbosity is not a virtue — reads like a caveat. It changed an answer. Decisions 7, 8 and 9 each introduced an [incomplete] marker, so a freshly scaffolded operation would have arrived three-quarters placeholder:

// before: the generator writes a placeholder per hole
type ApplyReply = [incomplete];
(:ok, ApplyReply) Apply(Order o, Command c);
Apply(o, c) -> [incomplete];

// after: one marker per declaration, holes enumerated by the compiler
[incomplete]
(:ok, ApplyReply) Apply(Order o, Command c);

type ApplyReply = [incomplete];

Two markers, not three and not one. The rule is one per declaration, not one per hole: what collapses into the function’s marker is everything internal to it — the missing clauses, the undecided boundary body — because those are residuals the compiler computes rather than facts only the author knows. What keeps its own marker is anything that must resolve as a name, since an unresolvable name is a broken file rather than a deferred decision. The substance of 7 and 9 survives; the enumeration moves onto the diagnostic channel, and cost moves off the human reviewer.

A smaller instance from the same session, applied to the skeleton itself: the diagnostic printed the residual is the clause you must write. beneath every inexhaustive error. It was cut. no clause matches: plus the head already says it; the trailer was the compiler narrating its own theory, which is what a design document is for.

What it hands on

A measurement the skeleton owes — the code-size cost of decision 6’s cause map at showcase clause counts, stacked on ticket 12’s failure arm. It is the twelfth skeleton debt and the second whose cost lands in emitted code rather than in the compiler; the honest worry is that a cause map is plausibly proportional to the type it describes where 12’s arm measured constant.

A dependency — decision 5’s JSON encoding inherits ticket 16 §4’s language-published serialisation mapping, which is owed and unwritten.

A question to ticket 22 — how the marker is spelled. Attribute, keyword or convention is 22’s subject exactly, and 22 is deferred. Three properties are fixed regardless: it is a fact in the file, one per function, and CI refuses it. That last makes it the first construct in the language whose purpose is to be removed before shipping — which is itself an argument for enforcement, the axis ticket 21 found nothing gives you alongside revisability.
