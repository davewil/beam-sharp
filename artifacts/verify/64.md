## Task 3: the hole, tested hard

(a) A caller that matches on the result: confirmed. `Check(Wrap(x, true))` with Check(:nothing)->false gives :false for x=:nothing. A second caller using `Wrap(x, true) switch { :nothing => false, _ => true }` (module E1) also gives :false. A caller with a local `var r = Wrap(x, true)` then `r switch {...}` (E2) gives :false. No diagnostic in any of them. So the program is accepted even when the call is not passed through a `term`-typed helper.

(b) Is it an instantiation problem or would 68/F31 refuse an inferred `option<term>` elsewhere? Positions tried:

| Position | Result |
|---|---|
| inferred local binding `var r = Wrap(x,true)` | accepted, wrong answer (E2) |
| inferred switch subject `Wrap(x,true) switch {...}` | accepted, wrong answer (E1) |
| helper with `term` param receiving Wrap's result | accepted, wrong answer (A1, B1) |
| tuple return `(option<T>, int)` from generic, caller at T=term | accepted (B8); the inferred position carries the absorbed shape |
| written return annotation `option<term> G(...)` returning Wrap(x,true), x, or :nothing | refused, error at the return type column (C1, C2, C3) |
| written parameter `option<term> o` | refused, "in Take" / "in Unwrap.o" (B2, B3) |
| generic `option<T> Id<T>(T)` called from `option<term>`-typed function | refused at G's own declaration (B6) |
| `list<option<T>>` from generic, caller declares `list<option<term>>` | refused at caller declaration (B7) |
| switch arm yielding Wrap(x,true) in a `term`-typed function (E3) | accepted (no collapse diagnostic) |
| explicit instantiation `Wrap<term>(x,true)` | not possible: "user code has no instantiation syntax" (B5) |

So the cause is: the check runs on written types. A type produced by substituting T at a call is never scanned. An *inferred* option<term> is refused nowhere.

(c) Calling Wrap from a function typed `option<term>` is refused. Exact message (C1):
```
C1/m.bs:6:21: error: `:nothing` is absorbed by `term`
  in G
  the failure channel does not survive normalisation, so the type
  declared here IS `term`. No caller can write the failure clause,
  because no failure member is left to match.
  hint: tag it - (:some, term) | :nothing
```
Note the position is G's declared return type, not the call to Wrap. "Refused at declarations only" is accurate for the refusal (every refusal I produced was at a written annotation, none at a call or expression). It is incomplete as a description of the gap: it is not just "generics"; any value whose type is option<term> by inference (generic return substituted at T=term) is unchecked, as the table shows. The honest phrasing is "refused at written annotations only". F31/68 text (68 lines ~370) does say a parametric *alias* is checked at its instantiation in a signature; that is consistent, since that instantiation is written. Generic *function* return types are not covered.

## Circularity findings

None found. Details of what I looked for:
- P1's matrix is produced by bsc with stub bodies, but real-body rebuilds of every accepted row compile and run, and the refused rows are refused with real bodies as well. The stub did not manufacture the verdicts.
- P2b: the demonstrating caller (`Check(term r)`) is shaped to expose the loss, which is a setup choice, but the same wrong answer reproduces through a direct `switch` and a `var` binding that I wrote independently (E1, E2), so the finding does not depend on that helper.
- P3 is Erlang that builds its own map and its own two lookups; it demonstrates a property true by construction (any bare sentinel collides with a stored sentinel). It is an illustration of the hazard, not a discovery about bsc, and the brief uses it only as such.
- P4b compares maps:get/3 (BIF, no allocation) against maps:find/2 (allocates tuple); the brief states this itself. The bench is compiled and uses distinct functions; ordering reproduced 3/3. The magnitude is specific to that choice of lowering (a different tagged lowering, e.g. a guard-based hit test, would be cheaper) but nothing is hidden.
- P5 counts are plain greps, reproducible; they count substring occurrences, not semantic uses.

## Unsupported or wrong claims in the brief

1. Option A's code sample does not compile as written: `Map.Get(m, "name") switch { (:ok, v) -> v  :absent -> "anonymous" }`. B# switch arms use `=>` and a comma between arms (I got `syntax error before: '->'` with the same shape; the `=>`/comma form in E1/E4/E5 compiles). `Map.Get` is also unbuilt, so the sample cannot be run anyway. The Option B sample (`public Maybe<term> Find(...)` with no body) is also a fragment.
2. "refused at declarations only" is understated (see 3b/3c): the gap is any inferred option<term>, not only generic instantiation at T=term in a callee.
3. "the instantiation check ... independent of the choice" and "every option needs it": reasoned, not measured. No probe tests what such a check would break (e.g. Wrap itself would become uncallable at term, with no way to write a fix since user code has no instantiation syntax; the hint would apply to a function the author did not annotate).
4. "Every neighbour that has a bare lookup ships a tagged one beside it": true for Elixir and Erlang as run/cited. Gleam has no bare lookup, so it supports nothing here. Elm was not run (the brief says so).
5. "adds 3 heap words to every present option<int> that is an immediate today": true for small ints; in P4 the 0-word figure is for immediates only. Not a general claim for option<map>, which the brief's table does separate (+3 on a 6-word map).
6. citations at maps.erl:138/686 point at -spec lines, not definitions (still the right functions).
