## Findings (adversarial)

1. **"Stripped beams 744 to 1344 (+600, +81%)" is mislabelled.** `erlc +strip` is not a stripping option on OTP 25. The chunk dump in the brief's own probe still shows Dbgi (92), CInf (96) and Line chunks. I ran `beam_lib:strip` on the same sources: one=322, two_a+two_b=310+257=567, so the real overhead is **+245 bytes (+76%)**, not +600. The brief's "+600 bytes" (section 5 and Option A's counterargument) overstates the absolute cost about 2.4x. The ratio is similar, and the conclusion (small fixed per-module cost) survives. The unstripped numbers are not what the text says they are.
2. **"Six `=:= public` readers" is unsupported by probe 09's own output.** Probe 09 1a lists five readers (bs_api:152, 158; bs_check:365, 376; bs_emit:141) plus one constructor (bs_check:1524). Its grep pattern misses the `=/= public` readers: `bs_check.erl:299` and `bs_check.erl:479` (`V =/= public`), and `vis_source(public)` at `bs_check.erl:2465`. A `{public,Scope}` encoding would make those `=/=` sites silently treat a scoped function as private, which is exactly the failure the brief warns about. So Option B's cost is **understated** (at least 7-8 sites, not 6). The "6" also appears as "6 visibility readers" in section 5.
3. **Recommendation point 3 (the consumer "shrank") is only half supported, and the brief never reconciles the other half.** The stale claim is confirmed: ticket 24:221-234 and 22:393 say "every function is exported today" and "unclassified: RecomputeTotal/1". F12's private-by-default (amended 2026-08-17) postdates ticket 24 (2026-08-13), and probe 01 shows `--api` hides the private helper. But the ticket's worry is an agent writing tests for helpers. Under Option A, probe 02 shows `Shop.Orders.Tests` (a module in the subtree) **may** name `Internal`. A is Go-parity, but it permits the very test-targets-helper drift that motivates the ticket. The brief presents "tests inside the tree may name it" as a feature and never says it is at odds with the consumer.
4. **Missed naming collision.** `wayfinder/issues/41-imports-and-cross-module-scope.md:490` already uses `Internal/` in the layout diagram ("inside a module: SUB-MODULE, source-only (ticket 13)"). The brief says `Internal` "needs a grep of the tickets" and then asserts "the word Internal matches no C# meaning" without doing the grep. F15:217-237 corrects 41's gloss (sub-module is a file, not a subdirectory). I verified that `Shop/Orders/Internal/` compiles to a separate `Shop.Orders.Internal.beam` (F15 behaviour), so the prototype premise holds. The ticket-41 diagram is a stale use of the same name that should be reported.
5. **Estimates labelling.** B and C are labelled as estimates in the options, in section 8 and in the recommendation point 1 ("B needs ..."). However, point 1 states "A is the cheapest answer **measured**" while the comparator's cost is an estimate, and the Option A "30 lines" figure is a prototype that was not run through eunit or the gates (section 8 admits it). Section 5's table mixes "Option B sites to touch: 6" (a grep count, finding #2) with measured rows without marking it as an estimate. Minor, but "measured" in point 1 oversells.
6. **36.5x stacktrace-guard cost.** The ratio is against a trivial `X*3` callee, so it is a worst-case ratio, not a typical one. Absolute overhead is about 0.45 us per call (464560 - 11755 us over 1e6 calls). The guard is also `process_info(current_stacktrace)`, the only portable caller probe, so I judge the baseline fair enough for "not viable". The brief should state the absolute figure. The tail-call false reject (2c) has a proper positive control (2b). The ratio varies between runs (39.5 in my run), and all of this is OTP 25.
7. **Gleam null result cannot distinguish "unenforced" from "path dependencies are exempt".** There is no negative control: nothing in the probe shows a positive effect of `internal_modules` (docs hiding, a warning on hex deps). The brief correctly hedges to 1.5.0 and the file is labelled a documentation hint. The claim is weak but honestly worded.
8. **Go test claim is weak.** `go test ./orders/internal/recompute` tests the internal package itself, which is trivially "in the tree". It does not show a test file elsewhere in the parent subtree naming it. The brief's phrase "a `_test.go` inside the tree may name it" is correct but thinly demonstrated.
9. **Prototype / port patches.** The port edits (leex column stub, `~kp`, rebar hooks) cannot manufacture the results. Columns are not used semantically anywhere in the grammar or checker (I grepped; only `interp_token`'s `{L,C}` passthrough), and the baseline and prototype share the same port. The prototype patch applies cleanly. It is 28 added and 2 removed lines, as claimed. The known flaw (the namespace tier gives a misleading message) reproduces. The prototype was not run against the eunit suite, as the brief admits.
10. **Minor wording.** The brief says "no catch-all message/1 clause in bs_diag". There is a catch-all for the `unclassified` tag only (bs_diag.erl:2162-2167). Its "grep unclassified finds only bs_api:280, bs_diag:75" omits bs_diag:77, 708, 2167 and bsc.erl:897, all the same unrelated diagnostic tag. The conclusion is unchanged.

## Overall verdict
All probes that can run reproduce, and the headline numbers (6 to 7 yecc conflicts, 36-40x guard, Option A accept/refuse matrix, Go and Rust semantics) hold. The brief is not circular: BASE-vs-PROTO and parens-vs-brackets controls exist and can go red. It has real defects that should be fixed before it goes to David: (1) the mislabelled "stripped" size, +600 should be about +245; (2) the reader-count undercount, which also biases against B; (3) the unreconciled tension between the Option A test-module allowance and the ticket's consumer; (4) the unchecked `Internal` name collision with ticket 41:490; (5) "measured" in recommendation point 1 applied to a comparison with estimates. None flips the recommendation on its face, but points 3 and 4 weaken its rationale and should be surfaced.
