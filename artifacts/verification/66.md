## Circularity findings
- **T66f is not circular, but it measures the wrong thing for decision 5.** It is a genuine tool outcome (the compiler refuses). It
  answers "does the declaration check stop `atom | :none`", not "does ticket 15 §1's instantiation collapse interact with a union
  name in a pattern". The pattern path does not exist yet, so decision 5 cannot be measured. It can only be argued from "a lowered
  `C c` tests minted record tags and cannot match an atom", which is reasoning, not a probe.
- **lowering_cost is not circular on equivalence.** The three forms behave identically (row 15). It is weak, not circular, on
  timing:
  - It measures only the last member of 20, which is the worst case for the guard chain and the dup chain. I measured the other
    positions (row 18).
  - The loop is a remote call, `M:'Handle'(Arg)`, which costs about 40 ns of the 42 ns measured. That overhead dominates and hides
    dispatch differences.
  - It is a single process with a warm-up call. All three forms are pure Erlang, not `bsc` output, so it says nothing about what
    `bsc` would emit.
- **Gleam row 20** shows the `as` form compiles. It is not evidence that the analogous B# lowering is a single-clause tag
  disjunction (Gleam duplicates the head).

## Corrections the brief needs
1. Replace "**Decision 5 is answered.** `type U = atom | :none` followed by `Take(U u)` is refused at the declaration ... No
   interaction" with: "**Decision 5 is argued, not measured.** Ticket 15 §1 rejects an absorbed failure member on generic
   instantiation (`option<atom>` is refused: `:nothing` is absorbed by `atom`). T66f shows the same family of check on a declared
   union (`atom | :none`). A lowered `C c` would test minted record tags, so it cannot reach an atom member; that is reasoning, and the
   pattern path cannot be probed until `C c` exists."
2. Add: "A union of a record and a record-shaped map (`A | { Id: int }`) is accepted at declaration; the open pattern `{ Id: _ }` then
   matches an `A`, and with it first the compiler warns the later clause is unreachable. Absorption is not caught at declaration for
   every overlap."
3. Replace "ticket 12 §1 ... so the counterargument is the field's habit, not the project's" with: "ticket 12 §1 states the principle for
   non-exhaustive functions; applying it to an unreachable clause is an extension. Ticket 66 itself points at §2." The ticket
   also reads "weigh against ticket 12 §2".
4. Replace the sizes table caption with: "sizes measured with the repo checkout path embedded in the beam; absolute values shift by
   about 28 B with the cwd (a clean copy elsewhere gave 956/860/896 and 2944/1012/1052). The ratios hold."
5. Replace "indistinguishable" with: "within about ±5 ns noise on a ~42 ns loop dominated by the remote call; positions 1, 10 and 20
   were all measured and none separated."
6. Change `bs_diag.erl:1162` to `bs_diag.erl:1160` (the `vacuous_clause` message).
7. State the exemplar 3 wording drift exactly (the ticket's quoted block reads "a part is named by the part: `Post(int n)` beside
   `Post(float f)`, one clause each."; the compiler now prints "a part is named by the part itself, lowercase — one clause taking
   `int` beside one taking `float`.").
8. Note that `type D = C | :none` (an alias inside an alias) is refused today with the same `not_a_record`. Option A's "resolve the
   alias" must therefore also resolve nested aliases, or this will be a follow-up refusal.
9. The brief says the project's rule makes the counterargument "the field's habit, not the project's". Add that the compiler already
   emits a warning, not an error, for another dead clause (`clause 2 of Take is unreachable`, rc=0), so a severity change would
   touch that diagnostic too.
