## Circularity
- narrow.patch removes only the tag test on private functions. `{ok,Tag} when Public` falls through to `_ when Public` (fails) then `_ -> {Pat,[]}`. Public behaviour is unchanged. `none` became `_`, which changes nothing else. Not circular, but the rows "narrow: First([forged Other]) = 77" follow by construction from deleting the test. What is real is that the private body does not object, which the map projection `o.Total` confirms. The patch only shows it.
- wide.patch removes `when Public` from the `none` branch only. It adds both the int guard AND the float guard on private functions. The brief says "kind test" and measures only int. The float case is real (probe 4) and not costed.
- `FirstOctet([200.5]) = 1` in c is genuine compiler behaviour (no patch involved).

## Adversarial probes (mine). Source: $S/work/v241/A/A.bs, driver f.erl; run `bsc --src-root . -o . A` under BSC_EBIN=$S/<variant>/ebin, then `erl -pa . -eval 'f:run(),halt().'`

Findings:
1. Wide DOES catch deep contents wherever the element reaches a private function (Deep row). The brief's "still does not check deep contents" is true only for elements that never reach a guarded function. The "needs the boundary walk" remark is overstated.
2. Out-of-range INTEGERS (`ChainOct([300])` returns 1 today) leak the same way as floats; the brief only mentions floats.
3. The tag test never applies to a union parameter (code comment at bs_emit.erl ~262: "single closed record"), so the forged Other in a `list<Order|int>` passes all three builds, including wide. The brief's "private tag test is what stops an alien record in a list" holds only for single-record types, and C does not make the six-call table "identical for tag" across unions.
4. Private->private depth does not matter: guard sits on each function, so wide/c stop at the first private callee.
