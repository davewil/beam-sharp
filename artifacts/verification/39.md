## 2. Circularity review and independent probes
Harness: same iteration counts for every variant, answers checked first (both tables), rotating order, minima only; the JIT compiles at load so no warm-up asymmetry. Prototype bsc emits via the same `from_abstr` path as the shipped bsc (bsc.erl:843), and p_none matches the shipped bsc, so the A/B/C comparison is not a different pipeline. No CIRCULAR probe found. Minor: I count 19 non-label/line instructions in Spin where the brief says 20.
- (b) Stripping `{tr}` does not change time: **DIFFERS in the direction, holds in the conclusion.** Stripped variants are consistently 1.4-2.8% *faster*, above the 1% floor, on 3/3 VMs in the brief's data and in mine (bsc 16.55 -> 16.09-16.25; Erlang 16.59 -> 16.32-16.38). I added the missing control (round-trip `'S'` -> `from_asm` without stripping) and it equals baseline (16.55-16.59), so the speedup comes from removing `{tr}`. The brief's own table row (16.31-16.41 vs 16.72-16.77) already shows it; the text says "unchanged". Conclusion (annotations buy nothing; if anything they cost 2% here) stands and is stronger. Edit the text.
- (c) Gleam's speed is its `inline` attribute: **REPRODUCED**, independently: pretty-printed Gleam's abstract code to .erl, deleted `inline` textually, erlc: 16.58-16.64 vs 10.47-10.49 with it. Also v_gl_noinline equals bsc/Erlang.
- (d) Wrap too big for inline_size 24: **REPRODUCED**. Spin calls: bsc with `inline` keeps the Wrap call at inline_size 24/30/40, drops it at 50+ (threshold between 40 and 50); 12.15 vs 10.47 ms. So the guard alone is the cause; the swap test in the brief is consistent.

Here Gleam 1.19.1 is 36% ahead because of `inline`. Either way, the 36-39% win of B/C is measured on one x86 box and one 4-function loop; the brief lists Apple Silicon as unmeasured but states the lead without that qualifier.
