## 2. Claim checks (a) to (e)

- (a) Q3 mis-aimed: CONFIRMED. `result<term,atom|term|binary>` refused (01 C, E, G); `result<int,term>` and `result<atom,term>` accepted (01 D, F). `absorbed/2` is at bs_check.erl:3282.
- (b) Silent instantiation at `term`: CONFIRMED (02 and my rerun). Also true when the polymorphic call is piped, or sits inside a lambda passed to `List.Map` (my cases C3, C4: stock compiles, patched refuses).
- (c) User `Maybe<T>` works at `term`: CONFIRMED (04, 03 R9; generic, nests, non-exhaustive switch refused).
- (d) Optional wire key with any term has no spelling: CONFIRMED (16).
- (e) Ticket 108 / `Map.?Get`: real (wayfinder/issues/108-the-second-forms-spelling.md). The brief's account is accurate: `?` after the qualifier's dot, `Map.Get` crashes, `Map.?Get` returns `:nothing`, return types unchanged (`option<T>`), unbuilt, ENG-324 first. 96 does list `Map.Has` (`maps:is_key`), line 224.

Contradictions with decided tickets (Decisions entries of 15, 48, 68, 108 read): none found in the recommendation. B leaves 15 §1, 68, 108, 48 Q8 intact. Option A would contradict 108's "return types unchanged: `option<T>`" and C would reverse 15 §1, and the brief says both. Two nits: (i) 96 line 224 lists a separate `Map.Find -> option<V>` row alongside `Get`; the brief never mentions it and it hits the same refusal at `V = term`. (ii) The brief cites "F34" for "Get raises on a missing key"; F34 is `raise`, and `Map.Get` is unbuilt, so that is design intent from 48 Q8 and 96 Q3, not a built behaviour.

## 3. Corrections needed

1. Probe 03 / brief line 146: "`ValidateAs<option<term>>` accepted" is an `--api`-only artefact. Full compile refuses it. Fix the index row and the probe (03/run.sh:11 should compile R6).
2. Brief §3 "within 3%" and §7.3 "no measurable time": reruns give about 1-8% for the tagged form (06) and 2-5% (07). Say "single-digit percent, noisy" instead.
3. Brief §7.3 and §5-C "demand is zero programs / 78 programs contain zero `option<term>`": the zero is produced by the compiler refusing the spelling. The exemplar prototypes did write it and hit the wall: `wayfinder/prototypes/32e-ffi-on-the-page.md:29,58` (`option<term> Fetch(...)`), `wayfinder/prototypes/25d-database-querying.md:148,402,509` (nullable SQL columns; "`option<term>` is `term`"), and `wayfinder/issues/25-exemplar-programs.md:521` ("`term` poisons every union it joins"). That is demand evidence for C or A, and it weakens the "zero demand" leg of the case against C.
4. Exemplar 25g's `triage_index.bs:38-43` citation is real (`find` is at line 42) but its header says it is "OUT OF THE WALKING SKELETON SLICE and does not parse today". The brief's "already looks up ... through the tagged foreign signature" overstates it; probe 12 B is the running evidence.
5. §8 "eunit incomplete" can now be closed (see 4).

## 4. Falsification of B plus the instantiation check

- TOCTOU between `Has` and `Get`: none. B# maps are immutable BEAM terms and both calls take the same bound value, so nothing can change between them. (It would exist for ETS or process dictionary, which are not `map<K,V>`.)
- Full test suite with the patch, in a full scratch copy including aoc/: `rebar3 eunit` finished in under 15 min with **All 1448 tests passed** (rc=0), including `every_aoc_program_still_compiles_test`. This replaces the author's 694/1 cut-short run.
- Patched vs stock `bsc` on all 78 repo programs I could compile: all 22 `compiler/examples/*` modules, the Shop sub-modules with `--src-root examples`, and aoc/2019, 2025 and bench: identical exit status, all exit 0. Exemplars 25a-g do not compile under either bsc (they are non-parsing targets), so they say nothing.
- False-positive hunt (patched refuses only the right things): `Head` through a still-open type variable (`First<U>`) accepted; `Head` at `string`, `(int,int)`, `list<term>`, `int` accepted; `result<T,string>` at `int` accepted; `Head` at `option<int>` elements refused, which matches the written form's `option<option<int>>` refusal. No wrongly refused legitimate generic code found.
- Holes the patch still leaves: none found in the call path I tried, other than the patch has no test or self-test of its own (the brief says this). Generic records (`record Box<T>`) are a syntax error today, so that route does not exist.
