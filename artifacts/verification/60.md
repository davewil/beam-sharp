Transitive flow of a hidden module's value through an allowed module's public signature (T8's call to Orders.Quoted) is unrestricted by v60a. Whether that counts as "naming" is a design choice the brief never states; the type-name route (T2/T5) is a real hole in "nameable only from inside Shop.**".
Not probed: record literals of the hidden type (qualified record literal syntax is rejected by the parser, T3 syntax error), and `implements`/protocol impls via `world_impls`.

Circularity: the Other/Other2/Other3 programs were written by the same author as the patch and cover only call routes (`using` module, `using` namespace, bare qualified). The brief's headline "Other3 is refused already, so `using` is the only naming gate" is true for calls and false for types (T2/T5), and the `--api` path. Conclusion in the brief ("a small checker change") is therefore understated: v60a is incomplete, not merely badly diagnosed.
