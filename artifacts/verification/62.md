# Verification of brief 62 (the outbound ABI)

## Verdict
The central claim holds: `:Shop."New"(1)` reaches a PascalCase export on Elixir 1.14.0. The corpus figures are slightly undercounted, and one cited precedent was not stated. The omitted precedent is ticket 32, which closed any PascalCase-to-snake_case rule. Sentences that need fixing are listed below.

## Circularity findings
- `Shop.erl` hand-writes `new/1`. `:Shop.new(1)` works because the test file defines it. This is expected and the brief does not rely on it.
- `alias_cost.sh` is not circular, but it is an unfair stand-in for `bsc` output in two ways. It compiles without `debug_info`. With `+debug_info`, N=100 gives plain 15912 B and alias 22940 B, a delta of 70 B per alias. That is about 1.8x the quoted figure, and Gleam and rebar3 both build with `debug_info`. Adding a `-spec` per alias cost only ~12 B in my test, so the brief's worry about specs is smaller than its worry about `debug_info`. The alias is a one-line local call; a real emitter forwarding multi-clause or guarded heads could differ.
- `corpus_alias.py` has a real hole. Its regex class `[\w<>,\s\(\)\?\.]` cannot match `:` or `|`, so 12 signatures are skipped. They are tuple and atom-union return types such as `public (:noreply, State) HandleInfo(...)`, `public (:ok, int) Init(...)`, and `public :ok | :error Pick(...)`. They are the OTP-callback-shaped functions, the ones the brief says collide with the callback table. Collisions stay 0 after fixing, but the check was blind exactly there. The script has no self-test.

## Corrections the brief needs
1. In Measurements: replace "244 (file, name) pairs in 137 files" with "256 pairs in 142 files; `corpus_alias.py` misses 12 signatures with tuple or atom-union return types (its regex excludes `:` and `|`); 0 collisions either way".
2. Replace "BEAM bytes per alias ... ~39 B" with "~39 B without `debug_info`; ~70 B with `+debug_info` (N=100: 15912 -> 22940 B)". Add that the probe does not compile with `debug_info`.
3. Replace the Option B evidence clause "the callback table already proves the emitter can produce a snake_case atom" with "ticket 32 settled that no snake_case⇄PascalCase rule exists in the language, so B reopens it; the `bs_otp` table is a fixed lookup, not a rule".
4. Under "B# already emits one snake_case name per callback": say `bs_otp.erl:42` is a fixed table entry, and that without a `behaviour` line `HandleCall` stays `'HandleCall'` (ticket 35).
5. Under Option A's counterargument: replace "formatters/linters ... may rewrite them" with "the Elixir formatter preserves the quoted form; the one measured cost is that `elixirc` warns `:Shop."New"/1 is undefined` when the beam is not on the compile path".
6. Replace "(Gleam calling B#) ... not run" with "Gleam `@external(erlang, "Shop", "New")` emits `'Shop':'New'(Id)` and returns the map when called (Gleam 1.12.0); only a real B#-built beam was not tried".
7. State that `&:Shop."New"/1` was inspected in probe.sh but not called there.
8. In "Gleam": add that `pub fn NewOrder()` is a syntax error, so Gleam rejects PascalCase function names.

## What I could not check
- Elixir newer than 1.14. The runtime is Elixir 1.14.0 on OTP 25, though the Elixir binary reports it was compiled with OTP 24.
- A real `bsc`-emitted module. I did not build `bsc`, so the alias size cost is a hand-written approximation.
- Dialyzer on aliases.
- Gleam 1.18.1, which the ticket cites. The brief and I used 1.12.0.
