## Circularity findings
1. **shallow_leak.escript (partly circular).** The nested value is hand-built in Erlang with exactly 3 top-level keys, then `map_size =:= 3` is applied by hand. The pass is true by construction; the shallow guard never runs inside any B# program. It also tests only `map_size`, where ticket 26 describes `has_map_fields` + `map_size` (same outcome here, but not the same test). The non-circular content is (a) json:encode really prints the nested Secret, and (b) the bsc-emitted validator really refuses it. The brief's wording "confirms it on a concrete value" is fair for (a)+(b), not for "the test passes".
2. **guard_cost.escript.** `deep` is real bsc output; `shallow` is hand-written and discards a throwaway list per call. Fixed run order (deep first), 2 warm-up calls, only 20 reps at N=10000, results list retained during timing (same for all forms). Not circular, but the deep cost is an implementation cost: the happy path allocates a path binary (`iolist_to_binary([91,integer_to_list(I),93])`) per list element even when nothing fails. A lazy path would be cheaper, so 1.2-1.6x is not the floor for "a deep guard".
3. **crash_shapes.escript.** The bare-function_clause row is `erlang:error(function_clause, [X])`, a stand-in, but I checked it against a real clause-miss: same reason, same 18 B, same stacktrace shape (433 B vs 437 B). Not circular.
